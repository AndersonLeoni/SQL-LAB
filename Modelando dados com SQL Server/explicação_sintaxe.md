# Criando bancos e tabelas em SQL, MySQL e PL/SQL

## Introdução

SQL é a linguagem usada para consultar e manipular bancos de dados relacionais. MySQL é um sistema gerenciador de banco de dados que implementa SQL com extensões próprias. PL/SQL é a linguagem procedural da Oracle, construída sobre SQL, permitindo variáveis, condições, loops, procedimentos e blocos de código.

Por isso, **SQL padrão**, **MySQL** e **PL/SQL/Oracle** não são exatamente a mesma coisa. Os comandos básicos de criação de tabelas são parecidos, mas a criação do banco, os tipos de dados, o autoincremento e a forma de executar comandos dinâmicos podem mudar.

## Diferenças principais

| Característica | SQL padrão | MySQL | PL/SQL/Oracle |
|---|---|---|---|
| Natureza | Linguagem/ padrão de comandos relacionais | SGBD que implementa SQL | Linguagem procedural da Oracle, baseada em SQL |
| Criação de banco | Depende do SGBD; `CREATE DATABASE` não é universal | `CREATE DATABASE` ou `CREATE SCHEMA` | Normalmente o banco Oracle é criado por ferramentas administrativas; o usuário trabalha em um schema |
| Seleção do banco | Depende do SGBD | `USE nome_banco` | Não há equivalente usual a `USE`; o schema/usuário determina o contexto |
| Autoincremento | Depende do SGBD | `AUTO_INCREMENT` | `GENERATED AS IDENTITY` ou sequência |
| Data e hora atual | Depende do SGBD | `CURRENT_TIMESTAMP` ou `NOW()` | `SYSTIMESTAMP` ou `SYSDATE` |
| Bloco procedural | Não existe uma implementação única | Pode usar stored programs, com sintaxe própria | `DECLARE`, `BEGIN`, `EXCEPTION`, `END` |

O MySQL documenta `CREATE SCHEMA` como sinônimo de `CREATE DATABASE`.[cite:28] Já no Oracle, `CREATE SCHEMA` serve para criar objetos, como tabelas, views e grants, dentro de um schema; não representa o mesmo conceito de `CREATE DATABASE` do MySQL.[cite:29]

## Criando um banco no MySQL

### Sintaxe

```sql
CREATE DATABASE [IF NOT EXISTS] nome_banco;
```

### Exemplo

```sql
CREATE DATABASE IF NOT EXISTS loja;
USE loja;
```

`IF NOT EXISTS` evita erro caso o banco já exista. O comando `USE` define o banco que será usado nas consultas seguintes.

Também é possível escrever:

```sql
CREATE SCHEMA IF NOT EXISTS loja;
```

No MySQL, `SCHEMA` e `DATABASE` são equivalentes para essa finalidade.[cite:28]

### Opções de caracteres

```sql
CREATE DATABASE IF NOT EXISTS loja
    CHARACTER SET utf8mb4
    COLLATE utf8mb4_0900_ai_ci;
```

A escolha do conjunto de caracteres e da collation deve considerar o idioma, a ordenação e a necessidade de armazenar caracteres especiais.

## Criando tabelas no SQL

A estrutura geral de uma tabela é:

```sql
CREATE TABLE nome_tabela (
    coluna tipo_de_dado [restrições],
    coluna tipo_de_dado [restrições],
    [restrições_da_tabela]
);
```

Exemplo genérico, compatível com muitos bancos relacionais:

```sql
CREATE TABLE clientes (
    id_cliente INTEGER NOT NULL,
    nome VARCHAR(100) NOT NULL,
    email VARCHAR(150),
    CONSTRAINT pk_clientes PRIMARY KEY (id_cliente)
);
```

O SQL padrão define a estrutura geral de `CREATE TABLE`, mas detalhes como autoincremento, tipos disponíveis e opções físicas variam entre os sistemas gerenciadores. A documentação do MySQL, por exemplo, descreve sua própria forma de `CREATE TABLE` e seus tipos de coluna.[cite:27]

## Criando tabelas no MySQL

No MySQL, é comum usar `INT AUTO_INCREMENT` para gerar identificadores automaticamente:

```sql
CREATE TABLE clientes (
    id_cliente INT NOT NULL AUTO_INCREMENT,
    nome VARCHAR(100) NOT NULL,
    email VARCHAR(150) UNIQUE,
    PRIMARY KEY (id_cliente)
) ENGINE = InnoDB;
```

### Explicação

- `INT`: tipo inteiro.
- `NOT NULL`: impede que a coluna fique sem valor.
- `AUTO_INCREMENT`: gera o próximo identificador automaticamente.
- `PRIMARY KEY`: identifica cada cliente de forma única.
- `UNIQUE`: impede e-mails repetidos.
- `ENGINE = InnoDB`: especifica o mecanismo normalmente usado para suporte a transações e chaves estrangeiras.

## Criando tabelas no Oracle com SQL/PL/SQL

No Oracle, a tabela é criada com SQL. O PL/SQL pode executar esse comando diretamente no ambiente Oracle ou por SQL dinâmico dentro de um bloco.

### DDL executado diretamente

```sql
CREATE TABLE clientes (
    id_cliente NUMBER GENERATED BY DEFAULT AS IDENTITY,
    nome VARCHAR2(100) NOT NULL,
    email VARCHAR2(150),
    CONSTRAINT pk_clientes PRIMARY KEY (id_cliente),
    CONSTRAINT uq_clientes_email UNIQUE (email)
);
```

Diferenças importantes em relação ao MySQL:

- `NUMBER` é usado com frequência para valores numéricos.
- `VARCHAR2` é o tipo de texto usual no Oracle.
- `GENERATED ... AS IDENTITY` é uma forma de geração automática de identificadores.
- Não se usa `AUTO_INCREMENT` no Oracle.

### Executando DDL dentro de PL/SQL

Comandos DDL, como `CREATE TABLE`, podem ser executados dentro de PL/SQL usando `EXECUTE IMMEDIATE`:

```sql
BEGIN
    EXECUTE IMMEDIATE '
        CREATE TABLE categorias (
            id_categoria NUMBER GENERATED BY DEFAULT AS IDENTITY,
            nome VARCHAR2(80) NOT NULL,
            CONSTRAINT pk_categorias PRIMARY KEY (id_categoria)
        )';
END;
/
```

Nesse caso, `BEGIN ... END` é o bloco PL/SQL, e `EXECUTE IMMEDIATE` executa o comando SQL armazenado como texto.

## O que é uma Primary Key

A `PRIMARY KEY`, ou chave primária, identifica exclusivamente cada registro de uma tabela. Uma tabela pode ter uma chave primária simples, com uma coluna, ou composta, com várias colunas.

### Chave primária simples

```sql
CREATE TABLE produtos (
    id_produto INT PRIMARY KEY,
    nome VARCHAR(100) NOT NULL,
    preco DECIMAL(10, 2)
);
```

A chave primária não pode conter valores duplicados e não aceita `NULL`. Em geral, cada tabela deve ter uma chave que identifique claramente suas linhas.

### Chave primária composta

```sql
CREATE TABLE itens_pedido (
    id_pedido INT NOT NULL,
    id_produto INT NOT NULL,
    quantidade INT NOT NULL,

    CONSTRAINT pk_itens_pedido
        PRIMARY KEY (id_pedido, id_produto)
);
```

A combinação de `id_pedido` e `id_produto` precisa ser única. Esse modelo é comum em tabelas associativas.

## O que é uma Foreign Key

A `FOREIGN KEY`, ou chave estrangeira, cria um vínculo entre uma tabela filha e uma tabela pai. A coluna filha referencia uma chave primária ou uma chave única da tabela pai, ajudando a preservar a integridade referencial.[cite:11]

### Exemplo em MySQL

```sql
CREATE TABLE pedidos (
    id_pedido INT NOT NULL AUTO_INCREMENT,
    id_cliente INT NOT NULL,
    data_pedido DATETIME NOT NULL DEFAULT CURRENT_TIMESTAMP,

    CONSTRAINT pk_pedidos
        PRIMARY KEY (id_pedido),

    CONSTRAINT fk_pedidos_clientes
        FOREIGN KEY (id_cliente)
        REFERENCES clientes (id_cliente)
);
```

### Exemplo em Oracle

```sql
CREATE TABLE pedidos (
    id_pedido NUMBER GENERATED BY DEFAULT AS IDENTITY,
    id_cliente NUMBER NOT NULL,
    data_pedido TIMESTAMP DEFAULT SYSTIMESTAMP NOT NULL,

    CONSTRAINT pk_pedidos
        PRIMARY KEY (id_pedido),

    CONSTRAINT fk_pedidos_clientes
        FOREIGN KEY (id_cliente)
        REFERENCES clientes (id_cliente)
);
```

A tabela `clientes` deve ser criada antes de `pedidos`, porque a chave estrangeira depende da tabela pai.

## Ações da Foreign Key

As ações definem o comportamento quando o registro pai é alterado ou excluído.

### MySQL

```sql
CREATE TABLE pedidos (
    id_pedido INT PRIMARY KEY AUTO_INCREMENT,
    id_cliente INT NOT NULL,

    CONSTRAINT fk_pedidos_clientes
        FOREIGN KEY (id_cliente)
        REFERENCES clientes (id_cliente)
        ON UPDATE CASCADE
        ON DELETE RESTRICT
);
```

- `ON UPDATE CASCADE`: propaga a alteração da chave referenciada.
- `ON DELETE RESTRICT`: impede excluir o cliente enquanto houver pedidos relacionados.
- `ON DELETE CASCADE`: exclui os registros filhos automaticamente; deve ser usado com cuidado.
- `ON DELETE SET NULL`: coloca `NULL` na chave estrangeira, desde que a coluna permita `NULL`.

## SQL padrão, MySQL e PL/SQL na prática

### SQL genérico

```sql
CREATE TABLE departamentos (
    id_departamento INTEGER PRIMARY KEY,
    nome VARCHAR(100) NOT NULL
);

CREATE TABLE funcionarios (
    id_funcionario INTEGER PRIMARY KEY,
    id_departamento INTEGER NOT NULL,
    nome VARCHAR(100) NOT NULL,
    CONSTRAINT fk_funcionarios_departamentos
        FOREIGN KEY (id_departamento)
        REFERENCES departamentos (id_departamento)
);
```

### MySQL

```sql
CREATE DATABASE IF NOT EXISTS empresa;
USE empresa;

CREATE TABLE departamentos (
    id_departamento INT AUTO_INCREMENT PRIMARY KEY,
    nome VARCHAR(100) NOT NULL
) ENGINE = InnoDB;

CREATE TABLE funcionarios (
    id_funcionario INT AUTO_INCREMENT PRIMARY KEY,
    id_departamento INT NOT NULL,
    nome VARCHAR(100) NOT NULL,
    CONSTRAINT fk_funcionarios_departamentos
        FOREIGN KEY (id_departamento)
        REFERENCES departamentos (id_departamento)
) ENGINE = InnoDB;
```

### Oracle/PL/SQL

```sql
CREATE TABLE departamentos (
    id_departamento NUMBER GENERATED BY DEFAULT AS IDENTITY,
    nome VARCHAR2(100) NOT NULL,
    CONSTRAINT pk_departamentos PRIMARY KEY (id_departamento)
);

CREATE TABLE funcionarios (
    id_funcionario NUMBER GENERATED BY DEFAULT AS IDENTITY,
    id_departamento NUMBER NOT NULL,
    nome VARCHAR2(100) NOT NULL,
    CONSTRAINT pk_funcionarios PRIMARY KEY (id_funcionario),
    CONSTRAINT fk_funcionarios_departamentos
        FOREIGN KEY (id_departamento)
        REFERENCES departamentos (id_departamento)
);
```

## Alterando tabelas

Uma chave ou coluna também pode ser adicionada depois da criação.

### MySQL

```sql
ALTER TABLE clientes
ADD telefone VARCHAR(20);

ALTER TABLE pedidos
ADD CONSTRAINT fk_pedidos_clientes
FOREIGN KEY (id_cliente)
REFERENCES clientes (id_cliente);
```

### Oracle

```sql
ALTER TABLE clientes
ADD telefone VARCHAR2(20);

ALTER TABLE pedidos
ADD CONSTRAINT fk_pedidos_clientes
FOREIGN KEY (id_cliente)
REFERENCES clientes (id_cliente);
```

## Cuidados importantes

- Crie primeiro a tabela pai e depois a tabela filha.
- Use nomes claros para as restrições, como `pk_clientes` e `fk_pedidos_clientes`.
- Garanta que a chave estrangeira e a chave referenciada tenham tipos compatíveis.
- Evite usar `SELECT *` em consultas de produção; informe as colunas necessárias.
- Teste comandos `CREATE`, `ALTER` e exclusões em ambiente de desenvolvimento.
- Em MySQL, confirme que o mecanismo escolhido oferece suporte às restrições necessárias.
- Em Oracle, diferencie o banco de dados, a instância, o usuário e o schema; eles não correspondem exatamente ao modelo de `DATABASE` do MySQL.

## Resumo

`CREATE DATABASE` é uma operação típica do MySQL, enquanto no Oracle a criação do banco é uma tarefa administrativa e o desenvolvimento normalmente ocorre dentro de um schema. A criação de tabelas usa `CREATE TABLE` nos três contextos, mas os tipos e recursos específicos mudam. `PRIMARY KEY` identifica registros de forma única; `FOREIGN KEY` conecta tabelas e protege a integridade dos relacionamentos.
